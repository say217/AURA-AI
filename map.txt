Each uploaded image in app 5 triggers _predict_image() → _gradcam().
_gradcam() rebuilds a new Model graph and runs a full gradient tape backward 
pass per image to obtain the heatmap. Computing gradients roughly doubles the 
cost versus a pure forward pass, so Grad-CAM dominates latency there.

The page accepts multiple files at once and loops over them, doing synchronous
 work (load bytes → preprocess → predict → Grad-CAM → create two matplotlib 
 figures → write PNGs) for every file. When several files are selected, the
  user experiences the accumulated latency because everything runs serially 
  before the response is sent.

TensorFlow defaults to eager execution on CPU unless you have a configured
 GPU; PyTorch in app 3 may be picking up CUDA automatically via
  torch.device('cuda' ...). If TensorFlow is still on CPU, 
  ResNet-101 + Grad-CAM becomes noticeably slower than the PyTorch path.
